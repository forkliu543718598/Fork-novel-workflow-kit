# scripts 说明

本目录提供**脱敏后的流程骨架**，用于说明发布环节是怎么实现的。
**不是开箱即用的工具**——平台选择器、流程步骤、账号计费都会变，接手者需要按自己平台调整。

## 文件

| 文件 | 用途 |
|---|---|
| `publish_skeleton.py.example` | 逐章发布骨架：只读核对 → 逐章提交 → 回读核验 → 写回记录 |

## 怎么用

1. 复制 `publish_skeleton.py.example` → `publish.py`（去掉 `.example`）。
2. 把里面的 `YOUR_*` 占位符改成你自己的路径、Chrome 路径、作品 ID。
3. 按你所用平台的真实页面，核对/修改选择器与按钮文案。
4. **先用测试作品验证**，确认只读核对和回读核验都正确，再跑正式作品。

## 骨架里体现的关键设计（比代码本身更值得看）

1. **启动前只读核对**：先读平台已有章号，确定从哪里续发，绝不凭推断。
2. **逐字键盘输入**：富文本（如 ProseMirror）必须用 `keyboard.type`，`fill/paste` 不会进编辑器内部状态，平台字数会算 0。
3. **确认提交只点一次**：避免重复提交。
4. **提交后回读**：重新打开页面读正文核验，不能只看 DOM 或列表缓存。
5. **断点续传**：进度写 JSONL，失败重跑时跳过已成功的章。
6. **清浮层**：平台的"继续编辑"浮层会拦截点击，需要先清掉。

## 目录约定（脚本用到的，可按自己情况改）

```
YOUR_PROJECT_ROOT/
├── 发布记录/
│   ├── 发布用章节/第N章.txt     # 每行：第一行标题，之后正文
│   ├── ds_progress.jsonl        # 断点续传记录
│   └── ds_run.log               # 运行日志
```
