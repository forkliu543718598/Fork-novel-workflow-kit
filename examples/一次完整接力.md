# 示例：一次完整接力（从想法到发布）

这是一段**示意对话**，展示各角色怎么接力、每段该给什么。替换成你自己的角色即可。

---

## 0. 你（决策人）给一句想法

> 一个前端工程师，在世界 AI 集体失智后，靠手写代码被疯抢。题材要爽、要快节奏。

---

## 1. 主 Agent 派发给策划角色

> 用 `prompts/01-策划大纲.md`，把上面这句想法扩展成整本大纲，按模板 6 项输出。
> 只给想法和题材偏好，不要给细节；设定边界和伏笔清单要清楚。

**策划角色（Gemini）产出**：`大纲.md`（约 200 章的弹性估计）、人物卡、伏笔清单、分卷结构。

**你人工确认**：设定边界、伏笔清单。

---

## 2. 主 Agent 批量生成章节 spec

> 按大纲第 1–10 章，逐章生成 spec，用 `templates/章节spec模板.md`。
> 每章一句话核心事件 + 爽点 + 钩子 + 字数目标。

---

## 3. 逐章写审循环（示例第 3 章）

**主 Agent 给写稿角色的上下文**（只给必要部分）：

> 本章 spec（粘贴）｜上一章正文末段（粘贴）｜主角人物卡（粘贴）｜未收伏笔 F003（粘贴）｜设定边界（粘贴）

**写稿角色（Flash/DeepSeek）**：输出本章正文。

**主 Agent 给审核角色**：

> 本章正文 + spec + 设定边界，用 `prompts/03-审核.md` 六维度审。

**审核角色（Gemini）**：`判定=FAIL`，问题清单：
- 第2条设定冲突：主角提前知道了"AI 失智是系统性事件"，但大纲规定他此时只知道"AI 崩了"。
- 第5条硬性要求：spec 的章末钩子未出现。

**主 Agent 给写稿角色修订**（`prompts/04`）：只改这两处，不动其他。

**审核复审**：`判定=PASS`，修订轮数=1。

---

## 4. 写回 Obsidian（主 Agent）

1. 正文写入 `03-章节/第003章.md`
2. `07-进度.md` 改为"写到第3章"
3. 人物卡无变化 → 不动
4. 伏笔台账：F003 状态改为"已埋/待收"
5. `08-续写断点.md`：下次接第4章，当前悬念是……
6. 大纲实际章数暂与估计一致 → 不动

---

## 5. 全书完稿后发布（发布 Agent）

**第一步只读核对**：

> 平台已有第 1–38 章，最大章号 38，状态已发布。
> 衔接点：从第 39 章开始，不重复建书、不重发前 38 章。

**逐章提交**（每章）：

> 填序号39/标题（取原稿）/正文（逐字输入）→ 回读平台字数 →
> 下一步 → 提交 → 检测 → 确认提交（1次）→ 回读章节管理页确认落库。

**全书核验**：

> 翻页读全部章号：126 章，1–126 连续，缺章无，重复无。
> 写台账、验收报告、核验 JSON。

---

## 6. 巡检与复盘（定时）

> 今日巡检：无新增驳回；审核中 120 章、待发布 6 章。
> 数据周报：第 3 章完读率高，第 7 章掉读明显 → 建议下一轮大纲减少该类型铺垫。

---

## 这个示例体现的原则

1. 角色各司其职，主 Agent 只派发与汇总。
2. 写审分离，FAIL 给可执行修改点。
3. 每章 PASS 后先写回知识库。
4. 发布前只读核对，提交后回读核验。
5. 异常和数据回流反哺下一轮。
