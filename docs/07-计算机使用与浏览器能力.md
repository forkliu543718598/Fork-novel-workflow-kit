# 07 发布 Agent 需要什么浏览器能力

> 作者原话："后续上传直接是带 computer use 的 agent 就行。"
> 意思：发布这一步不挑模型，挑的是**能不能真实操作网页并读回结果**。

## 必需能力清单

| 能力 | 用途 | 不具备的后果 |
|---|---|---|
| 打开指定 URL | 进作家后台、章节管理页 | 无法开始 |
| 填写表单（文本域/富文本） | 填序号、标题、正文 | 无法提交 |
| 点击按钮 | 下一步、检测方式、确认提交 | 无法推进 |
| 读取页面文本/DOM | 核对字数、标题、状态、弹窗 | 无法核对，只能盲提交 |
| 翻页 | 章节管理页只显示最新若干章 | 误判缺章 |
| 断点续传/日志 | 几百章中途失败要能接 | 重来或重复提交 |

## 富文本编辑器（ProseMirror）的坑

作者实测：某平台正文编辑器是 ProseMirror。

- `fill()` / `insert_text` / `paste` **只改 DOM，不进编辑器内部状态**，平台字数仍为 0，会被"正文至少 N 字"拦住。
- 只有**真实逐字键盘输入**才会更新平台字数统计。
- 所以发布脚本用 `keyboard.type(body, delay=0)`，并在写入后用平台字数复核。
- 校验一律以"编辑器实际文本 + 平台字数"为准，不只看 DOM。

## 弹窗的两个坑

1. **弹窗文本不在 `body.inner_text()` 里**（arco/byte-modal 独立渲染），必须按按钮文本或 JS 查询容器来驱动。
2. **"有刚刚更新的章节，是否继续编辑？"浮层**会拦截所有鼠标事件，还会让字数显示 0。
   解法：JS 轮询点"继续编辑"清浮层；用 `focus()` 代替 `click()` 聚焦编辑器。

## 鼠标通道失效时的兜底

作者遇到过鼠标事件整体超时（`dispatchMouseEvent timed out`）：

- 刷新页面 / 重开标签有时能恢复；
- 清掉新手引导浮层（1/3、2/3、"我知道了"）后再点；
- 等按钮从 `disabled` 变成可用再点；
- 实在不行换 Playwright 脚本直连，别在一章上死磕。

## 怎么用：把发布任务交给 computer use Agent（照做即可）

> 这一节解决"我到底该怎么使唤这个 Agent"。不挑模型，挑能力；把提示词给它就行。

### 第 1 步：确认它具备能力

问自己一句：这个 Agent 能不能**打开网页、填表、点按钮、读回页面文字**？能，就可以用。
不能（比如纯聊天模型没有浏览器/工具），就换一个带 computer use 或浏览器能力的 Agent。

### 第 2 步：把三样东西交给它

1. **提示词**：把 `prompts/05-发布核对.md` 整段复制过去。
2. **配置**：书名、作品 ID、作家后台地址、章节范围（第几章到第几章）。
3. **授权边界**：明确"登录/验证码/实名/签约/完结由我本人做，你不要碰"。

### 第 3 步：让它先只读核对（关键点）

第一句话就要求它：**先只读核对平台已有章节，报给你确认衔接点，再动手提交。**
- 它会报：已有前 K 章、最大章号、各章状态。
- 你确认：只发 K+1 起，不重发、不新建重复作品。
- 这一步能挡掉"重复提交/发错书"这类最难回滚的事故。

### 第 4 步：让它批量跑，你只看产出

跑起来后不要一章一章盯，只要求它：

- 每章完成报一行进度：`章节=N | 标题=… | 平台状态=… | 进度=X%`
- 连续失败 2 次就停下来报告，不要无限重试。
- 全部跑完给三份产出：**台账、验收报告、核验 JSON**。

### 第 5 步：你自己验收

只看三件事：

1. **缺章为 0**：核验 JSON 里 1–N 连续。
2. **无重复行**：平台章节管理页无同名重复。
3. **状态口径对**："审核中/待发布"就按待发布记，别当已发布。

### 常见的两个疑问

**Q：一定要脚本吗，Agent 自己点不行吗？**
A：章数少（几章）可以直接点；几十上百章建议用 `scripts/` 里的骨架思路——
逐章点既慢又不稳，脚本能断点续传、失败重试，人不用守着。作者几百章就是脚本跑完的。

**Q：它中途挂了怎么办？**
A：看进度日志/JSONL，从最后一个成功的章号接着跑。这就是为什么每章都要写进度记录。

### 一句话模板（可直接发给 Agent）

```
用 prompts/05 的流程发布《〔书名〕》第〔START〕–〔END〕章。
先只读核对平台已有章号并报我确认衔接点，再逐章提交；
每章回读核验、写进度；连续失败2次停下报告；
全部完成后给台账、验收报告、核验JSON。
登录/验证码/实名/签约/完结由我本人做，你不要碰。
```

## 核验原则（最重要）

- 提交后**必须回读**：章节管理页出现该章、无重复行、状态正确。
- 平台列表"字数"字段有缓存，**是否改成功以重新打开页面读正文为准**。
- 全量核验要**翻页**，不能只看首页（默认只显示最新十几章）。

详见 `10-平台实战踩坑.md`、`11-全自动与零成本实战.md` 和 `scripts/README.md`。
