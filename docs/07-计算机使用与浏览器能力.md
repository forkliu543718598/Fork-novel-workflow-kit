# 07 发布 Agent 需要什么浏览器能力

> 作者原话："后续上传直接是带 computer use 的 agent 就行。"
> 意思：发布这一步不挑模型，挑的是**能不能真实操作网页并读回结果**。

## 必需能力清单

| 能力 | 用途 | 不具备的后果 |
|---|---|---|
| 打开指定 URL | 进作家后台、章节管理页 | 无法开始 |
| 填写表单（文本域/富文本） | 填序号、标题、正文 | 无法提交 |
| 点击按钮 | 下一步、检测方式、确认提交 | 无法推进 |
| 读取页面文本/DOM | 核对字数、标题、状态、弹窗 | 无法核对，只能盲提交 |
| 翻页 | 章节管理页只显示最新若干章 | 误判缺章 |
| 断点续传/日志 | 几百章中途失败要能接 | 重来或重复提交 |

## 富文本编辑器（ProseMirror）的坑

作者实测：某平台正文编辑器是 ProseMirror。

- `fill()` / `insert_text` / `paste` **只改 DOM，不进编辑器内部状态**，平台字数仍为 0，会被"正文至少 N 字"拦住。
- 只有**真实逐字键盘输入**才会更新平台字数统计。
- 所以发布脚本用 `keyboard.type(body, delay=0)`，并在写入后用平台字数复核。
- 校验一律以"编辑器实际文本 + 平台字数"为准，不只看 DOM。

## 弹窗的两个坑

1. **弹窗文本不在 `body.inner_text()` 里**（arco/byte-modal 独立渲染），必须按按钮文本或 JS 查询容器来驱动。
2. **"有刚刚更新的章节，是否继续编辑？"浮层**会拦截所有鼠标事件，还会让字数显示 0。
   解法：JS 轮询点"继续编辑"清浮层；用 `focus()` 代替 `click()` 聚焦编辑器。

## 鼠标通道失效时的兜底

作者遇到过鼠标事件整体超时（`dispatchMouseEvent timed out`）：

- 刷新页面 / 重开标签有时能恢复；
- 清掉新手引导浮层（1/3、2/3、"我知道了"）后再点；
- 等按钮从 `disabled` 变成可用再点；
- 实在不行换 Playwright 脚本直连，别在一章上死磕。

## 核验原则（最重要）

- 提交后**必须回读**：章节管理页出现该章、无重复行、状态正确。
- 平台列表"字数"字段有缓存，**是否改成功以重新打开页面读正文为准**。
- 全量核验要**翻页**，不能只看首页（默认只显示最新十几章）。
