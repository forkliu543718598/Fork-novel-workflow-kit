# 05 角色替换指南（自由选择）

**本工作流的核心设计：每个环节都可以换人/换模型，流程不变。**
拿到仓库的人按自己手头的工具、预算、偏好挑即可，不必照抄作者的选择。

## 角色总表

| 环节 | 作者实际用过 | 作者当前选择 | 可替换为 | 替换时注意 |
|---|---|---|---|---|
| 主 Agent（调度） | Codex → WorkBuddy Hy4-flash | WorkBuddy Hy4-flash | Codex、Claude、任意带工具调用的主模型 | 必须能"派发子任务 + 读写文件 + 操作浏览器"；免费期有时效 |
| 策划 / 大纲 | Gemini | Gemini | ChatGPT、Claude、网文专家、人工 | 要求按模板输出；设定边界人工过一遍 |
| 写稿 | DeepSeek、WorkBuddy 自带 4.1-flash | 4.1-flash（便宜） | DeepSeek、ChatGPT、人工 | 按 spec 写；每次只带必要上下文 |
| 审核 | Gemini | Gemini | ChatGPT、审稿专家、朱雀、人工交叉 | **不得与写稿同角色**；按六维度输出 PASS/FAIL |
| 知识库 | Obsidian | Obsidian | 本地 md 库、腾讯文档、数据库 | 目录结构保持一致；每章必写回 |
| 发布 Agent | WorkBuddy + Playwright；早期 Hy4 子 Agent | 带 computer use 的 Agent | Codex、WorkBuddy、Playwright 脚本、浏览器扩展 | 必须能操作真实网页并回读 DOM |
| 决策人 | 用户本人 | 用户本人 | 只能本人 | 登录/实名/签约/完结不外包 |

## 关于主 Agent 的选型历史（作者原话整理）

> "全程的主 agent 派发我一开始用 codex，后来用 workbuddy 的 hy4-flash，
> 因为 11 月 30 日之前免费。"

- 早期：Codex 做主 Agent，负责派发任务。
- 后来：换 WorkBuddy 的 Hy4-flash，原因是**当时免费期内、成本低**。
- 这是**历史选型，不是硬性要求**。2026-11 之后是否仍免费，请自己核实。
- 换主 Agent 不影响流程：只要它能派发、读文件、调浏览器，就能照 `06-主Agent派发.md` 干。

## 关于写稿角色的选型（作者原话整理）

> "deepseek 我目前用的是 workbuddy 自带 4.1flash 因为积分便宜，前期基本不花钱。"

- 首选标准：**便宜 + 够用**，因为正文量大。
- 前期用便宜模型跑量，关键章节（开篇、高潮、结尾）可以临时换更强的模型。
- 审核仍交给另一个角色，别让便宜模型自审。

## 关于 Gemini 在流程里的位置（作者原话整理）

> "最初大纲你当我选用了 gemini，只要给个简单想法，gemini 负责整大纲，
> 然后排大概多少集，然后开始 deepseek 到 gemini 的 loop。"

- Gemini 承担两个岗位：**开头的大纲策划** + **逐章审核**。
- 起点是一个简单想法，不需要详细规格。
- 大纲阶段定集数（弹性），然后进入写稿↔审核循环。

## 关于发布角色（作者原话整理）

> "后续上传直接是带 computer use 的 agent 就行。"

- 发布不挑模型，挑能力：**computer use / 浏览器自动化**。
- 能开网页、填表、点击、读回页面文本即可。
- 具体步骤见 `08-发布与状态写回.md`。

## 组合示例（任选）

| 组合 | 主Agent | 策划 | 写稿 | 审核 | 知识库 | 发布 |
|---|---|---|---|---|---|---|
| 省钱起步 | 免费 Flash | Gemini | 便宜 Flash | Gemini | Obsidian | computer use Agent |
| 质量优先 | 强模型 | Claude | ChatGPT | 专家 + 朱雀 | Obsidian | Playwright |
| 全人工审 | Codex | 人工 | 便宜模型 | 人工交叉 | Obsidian | 浏览器扩展 |

## 替换时的三条硬约束

1. **写审分离**，任何时候都别让同一个角色既写又审。
2. **状态写回**，换角色后第一步永远是读 Obsidian 库接上断点。
3. **提交核对**，发布角色必须回读平台真实状态，不能凭"点了提交"判断。
