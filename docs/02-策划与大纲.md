# 02 策划与大纲（Gemini 的角色）

## 为什么大纲先行

长篇小说最大的风险不是文笔，是"写到一半没得写"或"前后矛盾"。
先由策划角色把整本书的骨架搭好，写稿角色只负责往骨架里填肉，效率和一致性都高得多。

## 策划角色的输入

只需要一个**简单想法**，越短越好，例如：

> 一个前端工程师，在世界 AI 集体失智后，靠手写代码和老手艺被疯抢。

不要一上来就给几十条细节——让策划角色去扩，这才是它的价值。

## 策划角色必须交付的 6 件东西

用 `prompts/01-策划大纲.md` 驱动，产出：

1. **书籍定位**：题材、卖点、目标读者、一句话简介、书名候选（3–5 个）。
2. **世界观与设定边界**：世界怎么运转、金手指是什么、**哪些不能写**（如：不出现真实公司黑幕、无系统外挂）。
3. **人物卡**：主角/重要配角/反派的性格、能力、动机、人物关系、成长弧线。
4. **分卷结构**：分几卷、每卷核心矛盾、卷末高潮。
5. **章节规划与集数**：每卷大约多少章、全书**约 N 章**，并给出弹性说明。
6. **伏笔清单**：计划埋哪些伏笔、打算在哪一卷回收。

## 关于"排大概多少集"

- 策划角色给的是**估计值**，用于估算工作量和节奏，不是硬指标。
- 明确写进大纲："实际章数以故事需要为准，可增可减，不为凑数注水。"
- 作者实战中，两部书的实际章数都和初版估计有出入，属于正常。
- 完结不要为了"凑够 N 章"拖剧情，该收就收。

## 从大纲到章节 spec

大纲定稿后，让策划角色批量生成每章 spec（见 `templates/章节spec模板.md`）：
每章一句话核心事件 + 爽点与笑点 + 人物推进 + 伏笔操作 + 章末钩子 + 目标字数。

写稿角色只看本章 spec，不需要每次通读整本大纲——这也是省上下文的关键。

## 策划角色的可替换性

| 角色 | 适合 | 注意 |
|---|---|---|
| Gemini | 长文本结构、大纲整理（作者默认） | 输出Often结构清晰，需人工确认设定边界 |
| ChatGPT | 脑暴、爽点设计 | 结构可能松散，要求它按模板输出 |
| 网文策划专家 | 商业节奏、市场向 | 成本较高，可用于关键卷 |
| 人工 | 完全掌控 | 最慢但最准 |

无论谁做策划，**设定边界和伏笔清单必须人工过一遍**——这是后面所有章节的地基。
