# 04 Obsidian 知识库（外置大脑）

## 它在这套流程里的定位

不是"写字的地方"，而是**全书唯一事实来源 + 大模型的外置记忆层**。
长篇写作的三个硬伤——上下文超限、前后矛盾、伏笔断裂——都靠它补。

## 它补的三件事

### 1. 补上下文

任何模型都装不下 200 章正文。做法是每章开写前，Agent 从库里只读这几样：

- 上一章正文（或摘要）
- 本章 spec
- 人物卡（相关人物）
- 伏笔台账（未收的伏笔）

只读必要上下文，既不超限，又接得上。

### 2. 补逻辑一致性

人物性格、能力边界、世界观规则、时间线都落在固定文件里。
写新章前对照，审核时也对照，避免"这个人突然变聪明了""上章说不能用外挂这章用了"。

### 3. 补伏笔

伏笔台账三列：埋在第几章 / 计划第几章收 / 实际收没收。
每章结束更新，长线不会忘。全书完稿前扫一遍台账，未收的要么收掉要么删掉。

## 推荐的库结构

```
vault/
├── 00-首页.md              导航：指向下面所有文件
├── 01-大纲.md              整本大纲、分卷、集数估计
├── 02-章节spec/             每章一份 spec
│   └── 第001章.md
├── 03-章节/                 正文，按章号
│   └── 第001章.md
├── 04-人物卡.md             人物性格/能力/关系/成长
├── 05-伏笔台账.md           埋/收/待收
├── 06-设定边界.md           哪些不能写
├── 07-进度.md               写到第几章、累计字数
└── 08-续写断点.md           下次从哪接、当前悬念
```

目录示例见 `templates/obsidian-vault/`。

## 每章 PASS 后必须做的写回（六步）

1. 正文写入 `03-章节/第NNN章.md`
2. `07-进度.md`：章数 +1、累计字数
3. `04-人物卡.md`：有无变化
4. `05-伏笔台账.md`：本章埋/收
5. `08-续写断点.md`：下次从哪接
6. `01-大纲.md`：实际章数与估计有出入时更新

## 为什么换模型/换会话也不怕

因为所有状态都在库里，Agent 无论换成谁，开工第一步都是"读库"。
作者实战中多次换模型、换会话，靠 `续写断点.md` 无缝接上，没有重复或断线。

## 可替换方案

| 方案 | 适合 | 注意 |
|---|---|---|
| Obsidian | 本地 Markdown、双向链接、插件生态（作者默认） | 需手动提交 git 才能多端同步 |
| 任意本地 Markdown 库 | 只要目录结构一致 | 失去双向链接但够用 |
| 腾讯文档 / 在线库 | 多人协作 | 注意隐私与导出 |
| 数据库 | 结构化查询伏笔/人物 | 写作体验差，一般不必 |
