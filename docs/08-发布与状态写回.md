# 08 发布与状态写回

## 提交前：只读核对（不可跳过）

发布 Agent 开工第一步不是点提交，是**只读核对平台真实状态**：

1. 作品是否存在、书名是否一致。
2. 章节管理页已有章号、最大章号、每章标题。
3. 审核状态分布（已发布/审核中/待发布/审核不通过）。
4. 确认衔接点：平台已有前 K 章 → 只提交 K+1 起。
5. 记录原始证据（页面文本片段），用于事后对照。

**禁止**：凭 URL、草稿 ID、标签历史推断章序或状态；禁止重发已有章；禁止新建重复作品。

## 提交中：逐章流程

1. 打开新建章节页，等编辑器就绪（按钮从 disabled 变可用）。
2. 填序号（纯数字）、标题（取原稿，≥平台下限，不拼接正文首句）、正文（逐字输入）。
3. 回读平台字数，确认正文真的进去了。
4. 下一步 → 发布提示提交 → 内容检测（选不限次数的那种）→ 发布设置 → 确认提交。
5. **"确认提交"每章只点一次**。
6. 提交后回读章节管理页，确认该章出现、无重复行。

## 平台硬门槛（提前处理，别等驳回）

| 门槛 | 作者实测值 | 处理 |
|---|---|---|
| 标题字数 | ≥5 字 | 短标题在**策划阶段**就拟完整，不要发布时临时拼"标题｜正文首句"（会和正文重复，很难看） |
| 正文字数 | ≥1000 字 | 短章在写稿阶段补足场景细节，不改剧情；原稿保留 |
| 标题唯一 | 全书不重复 | 生成 spec 时查重；重名提前改一个 |
| 推广引流 | 禁联系方式/外链/邮箱域名 | 审核维度加"平台合规"；正文里不要出现真实域名、邮箱、外部平台名 |

## 提交后：状态写回（三份文件）

1. **台账**：每章平台状态、提交时间、证据原文、备注（如"扩写版""标题微调"）。
2. **验收报告**：平台章数、缺章列表、重复情况、状态口径说明。
3. **核验原始数据**：翻页读取的章号清单，JSON 保存。

状态口径铁律：
- "审核中 / 待发布" **不能**写成"已发布"。
- 只有平台明确显示"已发布"才算已发布。
- 平台提示"已提交，预计 N 小时完成审核"属于待审核，不是上架。

## 异常处理

| 异常 | 处理 |
|---|---|
| 提交后列表没看到该章 | 可能是分页/异步加载，翻页或稍后重查，**不要立即重提** |
| 平台提示"重复标题" | 改一个不重复的标题再提，记录改动 |
| 平台驳回（如推广引流） | 读驳回原文 → 改写正文 → 从修改页重新提交 → 回读核验 |
| 审核中不让你编辑 | 如实记录，等审核通过后再改，**不要删了重建** |
| 格式问题（如多余横线） | 批量清洗后逐章重提，每章回预览页核验 |

作者实战中两处典型整改：
- 第5章因"推广引流信息"被驳回 → 去掉明文域名/外部平台名/联系方式，改写后重提。
- 39–126 章正文混入分隔线 `——` → 批量清洗 4955 条后逐章重提。
