# 06 主 Agent 与任务派发

## 主 Agent 干什么

主 Agent（作者用过 Codex，后用 WorkBuddy Hy4-flash）是**调度者**，不是所有活都自己干：

1. 拆任务：把"写一本书"拆成策划、spec、逐章写审、写回、提交、巡检。
2. 派发给各角色：把对应提示词 + 必要上下文交给策划/写稿/审核/发布角色。
3. 汇总与记录：收各角色产出，写入 Obsidian 和台账。
4. 盯进度：每完成一章报进度，异常时停并说明卡点。

## 主 Agent 必须具备的能力

| 能力 | 为什么需要 |
|---|---|
| 调用/派发子 Agent 或切换模型 | 策划、写稿、审核是不同角色 |
| 读写本地文件 | 维护 Obsidian 库、记录进度 |
| 浏览器操作（或能交给发布 Agent） | 提交章节、回读平台状态 |
| 长任务守护/断点续传 | 几百章不可能一次跑完，中断要能接上 |

## 派发时的上下文原则

**只给必要信息**，不要把整本书塞给每个角色：

- 给策划：一句想法 + 题材偏好 + 模板。
- 给写稿：本章 spec + 上一章正文 + 相关人物卡 + 未收伏笔。
- 给审核：本章正文 + 本章 spec + 设定边界 + 六维度清单。
- 给发布：本章标题/正文 + 平台规则清单 + 配置。

这样既省 token，又避免无关信息干扰。

## 派发提示词

见 `prompts/00-主Agent派发.md`。核心要求：

- 每步先说明再操作；
- 每章完成立即报"进度 N/总数 = X%"；
- 一批最多 5 章，任何环节连续失败 2 次立即停止回话；
- 禁止假称完成、禁止把"审核中"写成"已发布"。

## 用 Codex 还是 WorkBuddy

- 作者早期用 Codex，后期用 WorkBuddy Hy4-flash，理由是当时后者免费。
- 两者都能做主 Agent；选你顺手、便宜、能调工具的那个。
- **免费期信息有时效**：作者记录是 2026-11，Hy4-flash 免费到 11-30；后来者以实际账单为准。
- 换主 Agent 不需要改流程和提示词，只要把提示词发给新的主 Agent 即可。
