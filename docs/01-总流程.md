# 01 总流程（逐步 SOP）

这份是"照着做"的主文档。每个环节的角色都可替换，替换方法见 `05-角色替换指南.md`。

## 阶段 0：准备（一次性）

1. 复制 `config.example.json` → `config.json`，填自己的书名、题材、路径、平台。
2. 用 `templates/obsidian-vault/` 建一个 Obsidian 库，作为全书唯一事实来源。
3. 确定角色组合（谁策划、谁写、谁审、谁发布），把对应 `prompts/` 提示词发给各自的角色。
4. 明确一条铁律：**写稿角色 ≠ 审核角色**。

## 阶段 1：从想法到整本大纲（策划角色）

输入：一句简单想法（例如"一个前端工程师在世界 AI 集体失智后靠手写代码翻盘"）。

策划角色要做四件事：

1. **扩写成书**：题材定位、核心卖点、目标读者、金手指、主线矛盾、结局方向。
2. **搭世界观与人物**：主要人物卡（性格/能力/动机/关系）、势力设定、设定边界（哪些不能写，如无系统外挂）。
3. **分卷与节奏**：分几卷、每卷核心事件、高潮分布。
4. **排大概集数**：给出"约 N 章"，并说明这是**弹性估计**——按故事实际需要伸缩，不机械凑数。

输出：`大纲.md`（用 `templates/大纲模板.md`）、人物卡初始版、伏笔台账初始版。
提示词：`prompts/01-策划大纲.md`。

## 阶段 2：章节 spec（策划角色，可批量）

在动笔前，为每章生成一份"章节 spec"：本章核心事件、笑点/爽点、人物推进、伏笔操作（埋/收）、章末钩子、字数目标。
作用：写稿角色照 spec 写，审核角色照 spec 审，双方有同一把尺子。
模板：`templates/章节spec模板.md`。

## 阶段 3：逐章创作循环（写稿 ↔ 审核）

这是全流程的心脏，循环直到 PASS：

```
写稿角色 按 spec 写正文
        ↓
审核角色 逐项审核 → PASS / FAIL
        ↓ FAIL（给出具体修改点，限次修订）
写稿角色 按修改点改
        ↓
审核角色 复审
        ↓ PASS
写回 Obsidian，进入下一章
```

- 审核维度：剧情连贯、设定冲突、人物表现、文字质量、是否覆盖 spec 的爽点/钩子、平台合规。
- **限次修订**：约定最多 N 轮，避免无限循环；N 轮仍不过就人工介入。
- 每章审核记录留档（PASS/FAIL、轮数、问题清单），模板 `templates/审核记录模板.md`。
- 提示词：`prompts/02-写稿.md`、`prompts/03-审核.md`、`prompts/04-修订.md`。

## 阶段 4：写回 Obsidian（每章必做）

PASS 后不要直接跳下一章，必须先更新知识库：

1. 正文按章号写入章节目录。
2. 更新 `进度.md`（写到第几章、累计字数）。
3. 更新 `人物卡.md`（本章有无性格/关系变化）。
4. 更新 `伏笔台账.md`（本章埋了什么、收了什么、还剩什么待收）。
5. 更新 `续写断点.md`（下次从哪接、当前悬念状态）。
6. 更新大纲的"实际章数"（如果偏离了策划时的估计）。

详见 `04-Obsidian知识库.md`。

## 阶段 5：全书完稿 → 提交平台（发布 Agent）

前提：全书所有章节 PASS 并已写回 Obsidian。

发布 Agent（带 computer use / 浏览器自动化）执行：

1. 只读核对平台真实状态：作品是否存在、已有章号、最大章号、标题、审核状态。
2. 确认衔接点：平台已有前 K 章 → 只提交 K+1 起，不重复建书、不重发已有章。
3. 逐章走平台流程：填序号/标题/正文 → 内容检测 → 发布设置 → 确认提交（**每章只点一次**）。
4. 每章提交后回读章节管理页，确认落库、无重复。
5. 全书提交后**翻页全量核验**（章节管理页默认只显示最新十几章，不能只看首页）。

详见 `08-发布与状态写回.md`、`10-平台实战踩坑.md`。提示词 `prompts/05-发布核对.md`。

## 阶段 6：写回与闭环（发布 Agent + 定时巡检）

1. 写台账：每章平台状态、时间、证据原文。
2. 写验收报告：平台章数、缺章、重复、标题合规、状态口径（"待发布/审核中"≠"已发布"）。
3. 定时巡检：查审核状态、驳回消息、章节格式异常，有异常生成待办。
4. 数据回流：定期导阅读/收益/追读数据，反哺下一次大纲。

详见 `09-闭环与巡检.md`，提示词 `prompts/06-巡检与复盘.md`。

---

## 铁律清单（违反过就会出事）

1. 写稿与审核必须分离。
2. 每章 PASS 后先写 Obsidian 再进下一章。
3. 集数是估计，按故事伸缩，不凑数。
4. 提交前只读核对平台，不凭推断。
5. 提交后回读真实状态，不把"点了提交"当成功。
6. "审核中/待发布"不能写成"已发布"。
7. 登录、实名、签约、完结由本人做。
8. 发现问题先修流程，不靠临时补救。
