# 11 全自动与零成本实战（从弄不好到一次跑完）

这份文档记录一套真实过程：**一开始用主 Agent 直接操作浏览器，弄了很久都弄不好；
后来换了一条路，几百章一次跑完。**
作者本人也说不清中间每一个技术细节，但结果和踩坑是真实的，写下来让别人别重走弯路。

---

## 一、一开始为什么弄不好（真实的失败过程）

最早的想法很自然：让主 Agent（WorkBuddy）像人一样，在浏览器里一章一章点"新建章节 → 填标题正文 → 下一步 → 确认提交"。

结果卡了很久，问题分三类：

### 1. 鼠标点击通道整体失效

- 表现：点击报 `CDP Input.dispatchMouseEvent timed out`，或返回"已执行"但页面毫无变化（**假成功**）。
- 截图工具也报过 `display surface not available`。
- 主会话、换子 Agent、把标签置前，都试过，仍不稳定。

### 2. 平台根本没有批量入口

- 章节管理页、新建章节页、帮助中心都查过，没有"批量上传 / 导入文档 / Word/TXT 一键分章"。
- 这意味着 196 章要逐章点，而逐章点的通道又不稳定。

### 3. 本地脚本直连浏览器也走不通（当时的判断）

- 尝试过用本地自动化脚本接管已登录的浏览器实例，但每 Agent 会话独占浏览器、标准调试端口未暴露、登录态文件被进程独占。
- 当时的结论是"脚本直连不可行"。

**这一阶段的教训（对别人最有用的一句）**：
> 别在坏掉的交互通道上反复撞。逐章点 196 次本身就不现实，通道再一卡，人会陷进去几个小时。

---

## 二、后来是怎么解决的（作者说不清细节，但路子很清楚）

破局不是"把点击修好"，而是**换了一条完全不同的路**：从"Agent 在页面里点"改成"**本地脚本在后台循环跑**"。

### 关键转折 1：发现点击通道会"自愈"

- 实测发现：**刷新页面后点击通道会恢复**；等按钮从 `disabled` 变成可用再点、先清掉新手引导浮层（1/3、2/3、"我知道了"），成功率大幅提高。
- 一开始断续成功过几章，说明不是模型不行，是页面/标签状态坏了。

### 关键转折 2：正文不进模型上下文

- 把每章正文从"贴进对话让模型读"改成"**脚本直接从本地文件读**"。
- 好处：196 章正文一个字都不进模型上下文，既省额度又不会因上下文太长出错。
- 进度实时写日志，成功/失败/跳过都有记录。

### 关键转折 3：本地脚本 + 系统自带 Chrome

- 用本地 Playwright 驱动**系统已安装的 Chrome**，用一个独立的浏览器配置目录保存登录态；用户**只扫码登录一次**，之后脚本自己跑。
- 不再依赖主会话的浏览器点击通道，坏通道的问题绕过去了。

### 关键转折 4：守护进程 + 断点续传

- 脚本每提交一章就写一条进度记录；哪里中断，重跑就跳过已成功的章。
- 另写一个"守护脚本"：发现主脚本退出就自动重启，直到全部处理完，然后自动出核验报告。
- 这就是"全自动"的落点：**人只在开头登录一次，后面不用管**。

### 关键转折 5：把平台的坑逐个按下去

过程中陆续遇到并解决：

1. **富文本是 ProseMirror**：`fill/paste` 只改表面，平台字数算 0；改成**逐字键盘输入**才生效。
2. **弹窗文本读不到**：弹窗不在页面正文里，改成**按按钮文案驱动**。
3. **"是否继续编辑"浮层**拦截点击、还让字数显示 0：先清浮层，用 `focus()` 代替 `click()`。
4. **平台硬门槛**：标题≥5字、正文≥1000字、标题不重复、不许推广引流——前置到写稿/审核阶段处理，短章用扩写版、短标题在策划阶段就拟完整。
5. **章节列表分页**：默认只显示最新十几章，全书核验必须**翻页读全量**。

作者原话："后来虽然我不知道你怎么解决的，但得写上去。"
——上面就是能还原出来的全部关键点，细节可能不全，但**路子和坑是真的**。

## 三、全自动到底自动到什么程度

| 环节 | 人工要做的事 | 自动完成的事 |
|---|---|---|
| 策划大纲 | 给一句想法、确认边界 | 展开全书、排集数、生成人物卡与伏笔 |
| 章节 spec | 无 | 批量生成每章写什么 |
| 逐章写审 | 无 | 写→审→FAIL 自动修订→PASS 自动写回 Obsidian |
| 提交平台 | **登录一次** | 逐章填表提交、每章回读核验、失败重试 |
| 全书核验 | 无 | 翻页读全量、出缺章/重复报告 |
| 异常整改 | 决策是否改 | 改后逐章重提并回预览页核验 |

**不能自动、也不该自动的**：登录、验证码、实名、签约、完结申请——这些只能本人操作。

## 四、全免费的成本构成（作者当时的账）

> 以下是作者 2026-11 的实际构成，**免费期和价格会变，后来者以自己账号当前计费为准**。
> 重点不是"永久免费"，而是"用便宜资源跑量、把贵资源用在关键处"。

| 环节 | 作者用的 | 为什么便宜 |
|---|---|---|
| 主 Agent | WorkBuddy Hy4-flash | 当时在免费期内（到 11-30） |
| 写稿 | WorkBuddy 自带 4.1-flash | 积分便宜，正文量大也能承受 |
| 审核 | Gemini | 只吃短文本，结构能力强 |
| 发布 | 本地 Playwright + 系统 Chrome | 脚本跑，正文从文件读不进模型，不烧 token |
| 知识库 | Obsidian | 本地免费 |

**省钱的三条原则**：

1. 正文量大 → 用便宜模型，别用最贵的逐字写。
2. 正文不进对话 → 让脚本从文件读，省掉最大的 token 开销。
3. 审核只给必要上下文 → 每章 spec + 上一章 + 人物卡 + 伏笔，别塞全书。

## 五、给别人接手的三句忠告

1. **先测再跑**：拿一本测试书、先跑 1–2 章，确认只读核对和回读核验都对了，再跑正式书。
2. **别在坏通道上死磕**：点击超时/假成功时，先刷新、清浮层、等按钮可用；还不行就换脚本，别耗几小时。
3. **交付看证据不看动作**：提交了不等于成功，要回读平台页面、翻页核验、写台账；没落地就明确写"未产出"。
